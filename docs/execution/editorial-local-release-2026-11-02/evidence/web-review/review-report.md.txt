## Required repairs

1. **Consume or reject all active canonical source content.** `site/build_book.py:52–91`, especially the token scan at 61–82, keeps only introduction content, part arguments and `input` chapters, then separately extracts bibliography entries. Ordinary valid prose, inline math and emphasis inserted between the chapter includes disappear without changing the extracted pages, parts, label inventory or bibliography. An active `include{review-extra}` plus its extra TeX graph entry is also ignored by rendering, yet `source_archive()` at 550–559 exports that file. This matters immediately for any acknowledgment or editorial text placed after the introduction. The strict converter must consume every supported body region and every active graph entry, or reject unexplained remainder/unused input. It may explicitly permit the known comments, whitespace, `clearpage`, `appendix`, and bibliography boundaries. It need not become a general TeX interpreter. Regression evidence: `review_cases.py`, cases `inter_include_valid_prose_math_and_emphasis` and `extra_active_include_not_rendered_but_archived` in `adverse-cases.json`.

2. **Preserve canonical author and affiliation metadata.** `site/build_book.py:337–343` removes `maketitle`; `read_latex()` at 356–362 retains only the abstract and clears the entire metadata map. The landing/header at 527–547 and 596–619 supply no byline. A Pandoc probe using `author{Igor Rivin\\Department of Mathematics, Temple University}` produces HTML containing neither the name nor the affiliation. Derive and display the approved canonical metadata, and preserve the Codex acknowledgment as canonical body content. Avoid a second manually maintained freehand byline. The baseline had an empty author field, so this is a required forthcoming-source integration fix, not a claim that the baseline author text was already populated. Evidence: `metadata-probe/`, `adverse-cases.json`.

3. **Normalize directory paths before containment and overlap checks.** At `site/build_book.py:689–697`, `Path.absolute()` preserves `..`, whereas `is_relative_to()` is lexical. A work path shaped as `outside/hop/../checkout/scratch` passes the outside-checkout guard although it resolves inside the checkout. The synthetic probe intercepts at `git_state`, proving the guard was passed without creating scratch, compiling, or touching the canonical checkout. Resolve normalized paths before containment/disjointness decisions while retaining explicit rejection of symlink ancestors. Apply the same rule to both work and output, including paths that alias one another. Evidence: `dot_dot_work_path_inside_checkout` in `adverse-cases.json`.

4. **Do not silently remove a numbered equation's number.** At `site/build_book.py:211–223`, an ordinary `equation` environment without a label normalizes to bare display Math and returns before recording a number. LaTeX numbers that equation. Unlike the unlabeled-align handling at 148–154, this case succeeds without recovering a compiled number or rejecting unsupported numbering. Add a bounded rejection or an authoritative recovery mechanism. The baseline contains no unlabeled ordinary numbered equations, so this is an adverse future-edit regression, not a present discrepancy among the 472 checked labeled equations. Evidence: `unlabelled_numbered_equation` in `adverse-cases.json`.

5. **Narrow or strengthen cached-compilation acceptance.** `site/build_book.py:419–450` accepts a self-asserted receipt containing the exact source-hash map and accepted baseline auxiliary file, but a ten-byte `not a PDF` file, nine references to a 24-byte PNG-header fixture, and no tool-version record. It returns this as a `fresh full-book and diagram compilation` receipt; the build copies the bytes at 742–750 and republishes that provenance at 793. Hash agreement authenticates the supplied bytes, not their format or their claimed compilation origin. This is confined to the optional reuse path; no observed fresh compilation is accused of being invalid. The smallest bounded repair is to disable reuse for this release, or accept only an independently trusted compilation receipt with mandatory schema/tool fields and actual PDF/PNG validity checks, and state the trust boundary accurately. Do not add a generic checkpoint framework or imply arbitrary self-authored manifests prove compiler origin. Evidence: `malformed_compilation_receipt_artifacts` and the deliberately invalid, clearly named files under `fake-receipt-fixtures/`. The positive control rejects a receipt whose source hashes do not match.
