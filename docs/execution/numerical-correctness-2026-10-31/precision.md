## Implemented contract

- `geometry.lobachevsky_mp`, `bloch_wigner_mp`, and `triangle_volume_from_points_mp` return mpmath `mpf` values. Conversion occurs inside a scoped `workdps` context, preserving decimal-string or sufficiently precise mp inputs without first converting through Python float/complex. `Decimal`, `Fraction`/rational, NumPy integer and NumPy binary floating scalar inputs also retain their numerical information: conversion uses decimal text, integer numerator/denominator, or `as_integer_ratio`, as appropriate. The scope restores precision on success and failure; it is not thread-local and is not an interval/error guarantee. Arbitrary custom `__float__` objects have no generic fallback.
- `lob_exact` retains its actual historical mpf return type as a documented legacy alias. `bloch_wigner_mpmath` retains a float result and its default use of the caller's current precision, with optional explicit `dps`.
- High-level triangle/hull/Delaunay/sphere entries now recognize `mode="mpmath"`; `exact` and `eval_only` remain aliases. High-level outputs remain floats. Qhull geometry and sphere/hull projection remain binary64. High-precision kernel evaluation cannot validate that topology or recover earlier lost digits. Kernel accumulation uses `mp.fsum` before final float conversion.
- Binary64 and mp Bloch–Wigner paths use `D(z)=-D(1/z)` and `D(z)=-D(1-z)` to reduce to `abs(z)<=1`, `real(z)<=1/2`. Binary64 reciprocal computation scales the components before squaring and divides by the scale last, avoiding overflowing squared magnitudes or denominators. Scaled log-magnitude evaluation avoids premature underflow in the magnitude. Finite real-axis values, including 0 and 1, return zero. NaN/infinite input is explicitly rejected rather than interpreted as an infinity limit.
- The mp path reflects near one before taking a reciprocal, avoiding cancellation in `1-1/z`. Reduced negative-real-side points receive the additional identity `D(z)=-D(z/(z-1))`; the new point has nonnegative real part and modulus at most `1/sqrt(2)`, avoiding the unstable negative-axis continuation observed during independent review. The binary64 kernel did not require this further change.
- The existing public `fast` defaults are retained for compatibility, by parent decision. They remain fixed-term approximations. New maintained reporting paths must explicitly select BW or mpmath and report the method; no automatic accuracy or precision certificate is inferred.

## Independent-review correction

The [independent review](precision-review.md) found a blocking failure in the first uncommitted MP implementation, source hash `6b779e418e9a5328404b7cb18be9c2cdf7226a6c480fe5e235df0490cceaa51e`. At 120 working digits, `D(-1+i*1e-150)` returned approximately `-4.727e-125`, instead of `+6.931e-151`; the analogous `1e-300` case also had the wrong sign and magnitude. The existing binary64 kernel passed that independent review.

The additional mp argument map described above corrects this failure. Its bound follows from `|z/(z-1)|²=|z|²/(|z|²-2Re(z)+1) <= 1/2` for `|z|<=1`, `Re(z)<0`; its real part lies between zero and one half. The resulting points lie in the convergent-series region of the installed mpmath dilogarithm implementation. Inspection of that installed source confirmed a series branch at `abs(z)<=0.75`. This is an implementation explanation and finite numerical validation, not a general error bound.

The [reviewed source snapshot](precision-reviewed-geometry.py) retains exactly those prior source bytes. The [correction replay](precision-negative-axis-probe.py), [before values](precision-negative-axis-before.json) and [comparison](precision-negative-axis-comparison.json) verify that snapshot's hash and rerun twenty signed cases at five negative real values with imaginary magnitude `1e-150` or `1e-300`. All current MP, triangle-volume and compatibility-wrapper regressions pass against the unreduced direct formula at 450 digits. The reference is also checked against the analytic first-order real-axis derivative. The two sources do not share the new argument map.

Reflection before inversion also improves the review's nonblocking near-one discrepancy: for the next binary64 value above one with imaginary part `1e-300`, the relative difference against the direct 450-digit reference falls from approximately `7.18e-112` to `2.63e-122` at 120 working digits. Explicit regressions cover both signs and the smallest binary64 subnormal height at minus one. This does not promise 120 correct output digits for arbitrary inputs.
