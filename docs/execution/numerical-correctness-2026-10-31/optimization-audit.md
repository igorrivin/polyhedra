# H3 optimization and threshold contract audit

Date: 31 October 2026. Audited integrated baseline: `285a6cb71473ba1f238983e062662cf890cbba05`. This is a read-only source review and bounded reproduction. No implementation, original repository, historical result, Git index or commit was changed. The outer evidence directory contains [the machine probe results](optimization-audit-probes.json).

## Findings

1. **The service reports the solver's cached objective instead of evaluating its returned coordinates.** `optimization.py:494–515` determines trial validity, trial volume and the winning trial solely from `result.fun`. It never checks that this value agrees with `result.x`. A controlled `OptimizeResult` for regular-tetrahedron parameters `(pi/2, pi/3)` with `fun=-100` produces `best_volume=100` and `success=True`; a fresh canonical evaluation of the returned parameters gives `1.0149416064096537`. This is a defensive contract reproduction using a mocked solver return, not evidence that normal SciPy currently returns an inconsistent objective. Existing polish tests deliberately use objective values inconsistent with their parameter fixtures, so those tests currently encode this unchecked trust.

2. **An invalid candidate can displace a valid candidate and abort the result.** With a valid first trial and a higher cached score paired with a NaN parameter in the second trial, final assembly raises `ValueError: optimization parameters must be finite`. The valid first candidate is lost because endpoint validation happens only after winner selection. Validate each endpoint before ranking it. A similar geometry/structure failure should be kept as an invalid trial rather than suppress a usable earlier candidate.

3. **Invalid trial diagnostics can make the result non-JSON.** A NaN-parameter trial with a penalty objective is correctly excluded from volume statistics, but its raw parameters survive in `OptimizationTrial.as_dict` (`:338–350`). A later good trial permits the service to return, after which `json.dumps(payload, allow_nan=False)` raises. The CLI (`optimization_cli.py:225–226`) and GUI (`bin/gui.py:133–134`) use the permissive JSON default, so they can emit nonstandard `NaN` tokens. The schema's number arrays do not themselves enforce finite IEEE values. The shared serializer needs an explicit finite-data contract; adapters should use strict JSON as a final guard.

4. **Convergence and a valid candidate are already separate and should remain separate.** An otherwise valid trial with `result.success=False` is retained with its numerical volume and `success=False`. This is appropriate for a useful finite candidate after a differential-evolution iteration limit. Tests at `test_optimization.py:264–386` deliberately preserve this distinction even after a successful local polish. Do not equate a positive volume with convergence, and do not add a global optimality/KKT claim to this stochastic search. If stronger status fields are added, preserve the raw solver status separately and document any schema-version implications.

5. **Threshold input validation silently turns undefined data into decisions.** `volume_threshold.py:303–315` classifies every nonfinite component as infinity. Replacing the regular tetrahedron's infinity vertex with NaN returns exactly the same volume (`1.0149416064096535`) instead of rejecting the input. `volume_exceeds_threshold(..., threshold=NaN)` returns `False`, which is an unsupported decision rather than a valid comparison. `series_terms=True` is also accepted as one Fourier term and gives `1.299038105676658` for the regular tetrahedron. Validate NaN separately from the documented infinity representation; require a finite real threshold and a positive integer term count excluding booleans. Clarify the implicit-infinity convention, which appears intentional and must not be silently changed into a finite-only-polyhedron API.

6. **Threshold documentation overstates precision.** `get_volume` at `volume_threshold.py:355–363` calls its float return “exact”. The module also calls itself entirely self-contained despite importing the canonical geometry kernel. Default Bloch–Wigner evaluation already exists and the explicit finite Fourier series is already distinct; there is no need to introduce a second special-function implementation. Document binary64 evaluation and an ordinary numerical threshold comparison. Values extremely close to a threshold are not interval-certified decisions. The current test at `test_correctness_regressions.py:149–180` appropriately tests separated thresholds, not certification at equality.

## Proposed bounded implementation

Owning files: `ideal_poly_volume_toolkit/optimization.py`, `optimization_cli.py`, `volume_threshold.py`; any serialization changes must update `docs/schemas/optimization-result-v1.schema.json` or intentionally introduce a new version. Existing entry-point names remain compatible. The shared `optimization_result_to_dict` should remain the only serialization owner; the GUI should only need a strict-writer change if any adapter change is needed.

- Freshly evaluate each finite, in-bounds candidate through the canonical binary64 geometry owner before candidate selection. Record the relationship between the cached optimizer objective and recomputed volume if introducing diagnostics. Recomputed evaluations are separate work from SciPy's `nfev`; account for or explicitly label them.
- Validate each candidate's finite geometry and complete boundary reconstruction before it can become the winner. Preserve valid nonconverged candidates with their original solver status.
- Retain invalid-trial evidence without exporting NaN/Infinity. Choose and document a backward-compatible schema representation (for example, omitted/nullable diagnostic coordinates) rather than inventing valid replacement coordinates. Make JSON emission strict.
- Fix threshold NaN/term-count validation and precision wording; preserve explicit fast-series behavior and the implicit-infinity convention. Do not claim certified threshold decisions without an enclosure method.
- Add meaningful tests for a stale cached score, an invalid higher-scored candidate following a valid one, strict JSON with invalid trials, a valid unconverged control, NaN geometry/threshold, and boolean term count. Update old mocked polish fixtures to have genuine objective values or to assert fresh evaluation explicitly.

The above is independent of the other workers' owned changes in `geometry.py` and `rivin_delaunay.py`, except that it consumes the canonical geometry contract. It requires no broad RL/H4/H5 or historical `research/ipoly` rewrite.
